# spec-ssg

## Goals

SSG is a library-first, client-server text editor whose authoritative editor and presentation state runs headlessly and is usable without any bundled UI. P0 delivers a high-performance C++ core, an in-process interface suitable for a TUI, and an HTTP/WebSocket server built with `../http` on Linux and Windows. It provides complete basic editing: open a directory; open, type into, select, copy, cut, paste, save, close, and reopen files in tabs; edit, read-only, and diff modes; per-file undo/redo; dirty badges; crash-safe scratch recovery; word wrap; mouse-wheel and scrollbar navigation; external-modification status and resolution; multiple selections; fast search and navigation; a command palette; configurable browser-safe shortcuts; split views; syntax highlighting; Lua commands; persistent CWD-focused workspaces; Git diff views; filesystem-watcher-driven live following; and a collapsible left panel for filesystem, Git, Tree-sitter, and future tree data. Presentation uses a monospace cell layout suitable for a TUI, a fixed header/middle/footer shell, and themes containing exactly 16 colors from one authoritative palette. Stretch goals are a desktop client through `../gridui`, streaming-output tabs including arbitrary image data, Debug Adapter Protocol support, and very-large-file support. A package marketplace, registry, package discovery service, compatibility promise for third-party package collections, blocking dialog, client-only editor behavior, or feature unavailable to standards-based browser clients is not a goal.

Priority:
- **P0:** headless/client-server architecture and measurable high performance.
- **P0:** in-process TUI consumption, Linux/Windows HTTP/WebSocket transport, Lua plugins, browser-safe keyboard and clipboard control, mouse input, file tabs/modes, CWD workspace, scratch recovery, Git diff views with live edit following, the specified header/middle/footer shell, collapsible tree panel, and exactly-16-color themes.
- **Core:** typing and deletion, multiple selections, per-file undo/redo, copy/cut/paste, dirty state, open/save/close/reopen, read-only enforcement, word wrap, scrollbar/wheel scrolling, find/replace including regular expressions, Goto Anything, symbol/line navigation, command palette, configurable commands, distraction-free mode, syntax highlighting, LSP, session restoration, and Linux/Windows parity.
- **Additional basic editor goals:** select all; character/word/line/document movement and selection; page movement; home/end; indent/outdent and configurable tabs/spaces; automatic indentation; line duplication/movement/deletion; comment toggle; bracket matching; configurable line endings and final-newline preservation; UTF-8 validation with explicit lossy-conversion refusal; current-file and workspace search; create/rename/delete files and directories with recovery; reopen last closed tab; local-client drag-and-drop file opening when the host grants locality; zoom/font-size as client presentation state; and accessible status/action labels.
- **Stretch:** `../gridui` desktop consumption, streaming-output tabs with arbitrary image payloads, DAP, and very-large-file editing.

## Design

`ssg` is a C++20 library target with transport- and renderer-neutral public interfaces. The library owns resource validity, state transitions, revision ordering, and input validation; applications own presentation, event loops, scheduling policy, and storage of credentials. Read [cpp-lib-values.md](../cpp-lib-values.md) before designing or changing the public C++ API. Its required values include RAII, explicit ownership, move-only resource owners, scoped enums and domain types, construction-time validation, descriptive names, and no required `init()`/`destroy()` sequence.

The authoritative unit is `EditorSession`. It owns a canonical absolute CWD, open `Document` objects, tab and split-pane topology, command registry, undo histories, Lua runtime, workspace services, and monotonically increasing session revision. A client attaches through `EditorClient`, receives an initial `SessionSnapshot`, submits typed `ClientCommand` values against an observed revision, and receives ordered `SessionDelta` values. The same command/delta protocol is used by in-process clients and serialized WebSocket clients; transport adapters may not contain editor behavior.

Feature modules integrate through two explicit seams. Each module exports an immutable `CommandSet` containing descriptors and handlers; `EditorSessionBuilder` registers those sets into one `CommandRegistry`, rejects duplicate IDs at construction, and dispatches every `ClientCommand` through that registry. Registration is explicit in `editor_session_assembly.cpp`; static initialization and self-registering global side effects are forbidden. Handlers receive a bounded `CommandContext` exposing the session revision, typed feature state, transaction boundary, status sink, delta sink, and immutable `InvocationPrincipal` rather than the transport or renderer. The principal contains client identity, origin (`in_process`, `websocket`, `lua`, or `system`), and host-granted capability IDs. The host creates in-process principals explicitly; WebSocket authentication resolves a principal before session attach; Lua uses its plugin capability set. Commands validate principal capabilities at the common dispatch boundary so direct and WebSocket calls cannot diverge.

Each feature also owns typed `FeatureViewState` and `FeatureDelta` values plus pure functions that derive them from a revision-stable state input. `SessionSnapshot` and `SessionDelta` are explicit aggregates of those typed sections; `editor_session_assembly.cpp` is the sole owner that invokes contributors and builds the aggregate. Feature tasks may add their own section types but do not edit aggregate/session/codec files. The early core vertical slice establishes the envelope, revision/base rules, document section, registry dispatch, and loopback WebSocket path before broad feature work. The later assembly task adds every accepted P0 command set and view section, after which protocol codecs serialize the complete aggregate. This keeps integration centralized without type-erased view data or client-side composition.

`Document` owns UTF-8 text in a balanced piece tree, a document revision, dirty state, mode, syntax state, recovery state, and transaction history. The piece tree references immutable original and append-only add buffers and stores subtree byte, newline, and display-metadata summaries. It is chosen over a gap buffer because separated multi-cursor edits do not repeatedly move one gap, and over a plain rope because immutable pieces naturally retain transaction spans for bounded undo and scratch journaling. Storage representation remains private so the stretch very-large-file feature can replace it. `EditorView` owns client-facing state such as multiple selections, viewport, wrap mode, active pane, focus mode, and panel visibility. Text mutation is an atomic `EditTransaction`: edits are expressed in pre-transaction byte offsets, are validated as non-overlapping, and are applied from highest to lowest offset. Typing replaces each non-empty selection or inserts at every caret; overlapping results are normalized deterministically. Every accepted transaction produces one history entry and one document revision. Adjacent typing and same-direction deletion entries coalesce into one undo unit when command kind, caret topology, adjacency, and a configurable 750 ms session-clock window match; navigation, selection changes, paste, newline, and non-edit commands break coalescing. Undo restores selections from before the unit, redo restores selections from after it, and a new edit after undo discards redo. Each file has a bounded undo/redo history configurable by byte budget. After an edit, cursor, selection, find-result, or undo/redo command, every client view displaying the affected primary selection minimally scrolls to reveal its primary caret; `view.reveal_caret` and `view.center_caret` provide explicit control. Positions crossing an API boundary contain byte offset, zero-based line, and zero-based display cell; stale or inconsistent positions fail with an actionable protocol error rather than being guessed.

`DocumentMode` is one of `edit`, `read_only`, or `diff`. Writable text files default to edit; files without write permission and explicit read-only opens use read-only; live diff tabs use diff. Read-only and diff modes reject mutation commands without changing state and publish an actionable footer status. Tabs expose mode, path, dirty/recovery state, external-modification state, and a dirty badge. Closing is immediate and non-modal: a clean tab closes directly; a dirty tab first requires an up-to-date scratch journal and becomes recoverable through `tab.reopen_closed`. Major state-losing commands retain a bounded compensating record: close reopens, reload restores the pre-reload buffer, overwrite-save retains a backup, and workspace rename/delete moves content to a session recovery area before final cleanup.

Scratch persistence is a core service configured with a host-provided root, defaulting to the user's cache location on Linux and local application-data location on Windows. Each process writes a locked session directory beneath a canonical-workspace hash; operating-system locks distinguish live sessions from crash remnants without PID guessing. A new process uses a new session ID and automatically restores the newest unlocked recoverable session for its workspace while preserving other live sessions. Saved documents are keyed by stable workspace identity; never-saved documents use generated `UntitledDocumentId` values and reopen as `Untitled N` tabs. Every accepted dirty transaction is appended asynchronously to a checksummed per-document journal and periodically compacted to an atomic snapshot. The default durability target is 100 ms after acceptance; the footer exposes pending or failed durability. Content, dirty state, mode, and tab topology survive restart, but undo/redo history does not. Opening and closing the program does not present a dialog; startup restores from the newest complete records, and corrupt/truncated tails are discarded after the last checksum-valid record. Session shutdown stops accepting mutations, flushes already-open journal descriptors, and completes without a user decision.

Text remains UTF-8 internally. Rendering and hit testing operate on grapheme clusters and terminal-style display cells. Tabs advance to the configured tab stop; combining marks occupy zero additional cells; control characters render as visible replacement glyphs; and wide graphemes occupy two cells according to the project-pinned Unicode width tables. The core emits cell runs and incremental invalidation ranges, not pixels or terminal escape sequences. This permits a TUI, browser, and GPU renderer to consume the same layout while keeping rendering out of the editor core.

`EditorSession` also owns the complete UI shell state so every attached client renders the same active tabs, panel visibility, focus, diff-follow state, header, and footer. `EditorView` stores each client's viewport dimensions and resulting pane scroll offsets inside the library; these are authoritative per-client state because terminal and browser dimensions may differ. The shell is a cell grid with three vertical regions. The first row is a full-width status header containing the CWD/current path, active command or mode, and command-palette query when open. The last row is a full-width status footer containing file size, detected file type, encoding, line ending, Git repository and branch, background activity, follow-edits state, and the currently configured resume-follow binding. Footer statuses form a bounded priority queue; the footer shows the highest-priority item, action bindings, and queue position, while `status.next`, `status.previous`, and `status.dismiss` navigate it and `status.invoke_action` invokes a generation-checked selected action. Rows between header and footer form the middle: an optional collapsible left panel and a right editor area. The editor area begins with exactly one shared tab-bar row, followed by the current tab content or an empty-state surface, with exactly one rightmost scrollbar column. Split panes subdivide only the editor content rectangle below the shared tab bar; each pane reserves its own one-column scrollbar. Non-modal `PromptSurface` rows may temporarily consume the top one to three content rows below the tab bar for path entry, find, replace, settings, and command arguments; they do not block other commands or hide the underlying document state. `data/ui/status_fields.json` declares deterministic collapse order: header fields retain command-palette/active-command, current path, then mode; footer fields retain actionable status, follow state/resume binding, background activity, encoding/line ending, Git branch, Git repository, file type, then file size. The left panel collapses before editor content. No region receives a negative or overlapping rectangle.

Commands are stable identifiers with typed arguments. All keyboard, mouse, clipboard, palette, Lua, LSP, filesystem, and transport actions resolve to the same command registry. The normative required-command catalog is the union of the explicitly listed command IDs in all P0 feature specs; `data/required-commands.json` is an independently reviewed transcription, never a list generated from the implementation. Except for process/session lifecycle, transport authentication, raw platform I/O, and host capability grants, every user-visible command is callable from the versioned Lua API. The backend neither captures nor interprets platform input: each client converts browser, terminal, or desktop events into typed semantic commands using the keymap and hit-test metadata supplied by the API. The default keymap is authoritative data, not hard-coded client behavior. Its required editing, selection, navigation, tab, pane, panel, file, search, settings, status, and palette actions must have bindings deliverable by current Chromium, Firefox, and WebKit without relying on reserved or browser-specific combinations. Clients handle IME composition and submit committed UTF-8 insertion commands. Mouse clients convert cell hit targets into caret, selection, scroll, tab, splitter, and panel commands. Wheel scrolling and scrollbar dragging update the same per-client `EditorView` scroll command path.

Clipboard access is an asynchronous client capability because browsers own clipboard permission, while `EditorSession` owns an internal structured clipboard register. Copy always updates the register and publishes selected UTF-8 text in a best-effort `ClipboardWriteRequest`. With empty selections, copy captures complete lines including terminators; cut captures and removes those lines. Cut atomically updates the register and document, remains undoable, and reports if system clipboard export fails. Paste under a qualifying secure-context user gesture requests system text and falls back to the internal register on denial or unavailability; palette, Lua, or remote paste requests without a gesture use the internal register and publish a footer action for an optional system-clipboard paste gesture. A register containing one fragment per caret distributes fragments one-to-one when caret counts match; otherwise each caret receives the full plain-text payload. Client responses carry request and observed document revisions, and stale responses do not mutate. In-process clients use the same request/response API.

Tabs reference typed content models rather than files only. P0 tab kinds are document, live diff, read-only text output, search results, and tree view; split panes can display any P0 tab. File commands open by stable workspace-relative identity, avoid duplicate editable documents, save atomically through a same-directory temporary file and rename, close immediately under the recovery contract, and reopen from the bounded recently-closed list. `file.new`, `file.open`, `file.save_as`, and `file.rename` use the non-modal path `PromptSurface`; path completion is rooted at the CWD, validation is live, submit is immediate, and cancel changes no state. Saving an untitled document assigns the submitted workspace-relative identity only after successful atomic replacement. Drag-and-drop is not a general remote-browser workflow. When the host grants a principal the `local_file_drop` capability, a browser may send dropped bytes and suggested filenames through `file.open_dropped_content`; each becomes an untitled buffer without external path authority. In-process clients receive no capability automatically—the embedding host must grant it. Suggested names are bounded, sanitized display labels only; they never become paths until `file.save_as` performs normal path validation. Dropped bytes use the same BOM/encoding/NUL pipeline as opened files, including read-only binary or decode-failure states. Remote or locality-unknown clients do not expose this interaction, and common dispatch rejects the command without the host-granted capability. `file.open_dropped_content` is an ingress-only command: it has no key binding or palette entry and is explicitly excluded from Lua command parity. Opening a directory creates or replaces the canonical-CWD workspace through one reversible session command; replacement preserves the prior workspace recovery record. Word wrap is a per-view toggle that changes visual rows without changing document bytes or line identity. Stretch output tabs add a framed byte stream whose declared MIME type allows arbitrary image data; clients may reject unsupported MIME types without corrupting the stream or session.

`SettingsModel` owns typed values at default, user, workspace, language, and document scopes, resolved in that order with the most specific present value winning. It covers indentation width/style/detection, automatic indentation, line-ending and final-newline policy, encoding, word wrap, theme, keymap, search options, history/recovery budgets, and other declared settings. User settings persist beneath the user configuration root; workspace settings persist in host storage keyed by canonical CWD unless the user explicitly exports a project file; language/document overrides persist with session recovery. `settings.set` and `settings.reset` validate before mutation, publish deltas immediately, and create a compensating status action. Language syntax supplies default comment tokens, bracket pairs, and indentation rules but settings may override allowed values.

File decoding detects UTF-8, UTF-8 BOM, UTF-16LE BOM, and UTF-16BE BOM. Files without a definitive BOM use configured/default UTF-8; a failed decode opens read-only bytes with actionable `file.reopen_with_encoding` choices including UTF-8, UTF-16LE/BE, Windows-1252, and ISO-8859-1. Internal text remains UTF-8, while save re-encodes to the selected encoding and preserves BOM policy. Footer status exposes encoding and LF, CRLF, CR, or mixed line endings. `file.set_encoding`, `file.set_line_ending`, and `file.set_final_newline` are reversible; mixed endings preserve per-line terminators until an explicit normalization command.

The workspace is rooted at one canonical CWD. Filesystem access is constrained to that root by default; explicit policy may permit following a symlink or opening an external path. Relative paths in protocol and persisted state are relative to the CWD. The collapsible left panel is a host for named tree providers. Filesystem, Git, and Tree-sitter symbol providers share stable node IDs, labels, optional icons, expansion state, and provider commands. Providers publish deltas so collapsing the panel stops presentation work without destroying provider state. Distraction-free mode hides all non-editor chrome without changing document, tab, split, or panel state.

Filesystem watching is supplied through an injected `FilesystemWatcher` interface implemented with inotify on Linux and `ReadDirectoryChangesW` on Windows. Adapters normalize create, modify, rename, delete, and overflow events for paths beneath the CWD. Events are debounced by stable file identity and path, then processed on the session command executor. A watcher event reloads clean buffers from disk and marks dirty buffers externally modified rather than overwriting unsaved edits. The footer exposes immediate `external.reload`, `external.keep_buffer`, and `external.open_diff` commands; reload remains reversible from the recovery record. Saves initiated by SSG are correlated with their resulting watcher events and do not create duplicate status or follow transitions. Watcher overflow invalidates incremental assumptions and triggers a bounded CWD rescan.

`DiffModel` computes line-oriented hunks without invoking a shell. For a tracked Git file, the baseline is the index; for an untracked file, the baseline is empty. Outside a Git worktree, watcher startup seeds a bounded content snapshot for each eligible existing file before publishing events; the first modification compares against that seed, each accepted event advances the acknowledged baseline, and a newly created file uses an empty baseline. Rename and delete events retain the prior path/content needed to describe the change. A live diff tab has stable identity per workspace-relative file and contains the current file content plus added, removed, and modified line annotations; it is not a separately editable copy. Git index or branch changes recompute affected baselines.

Follow-edits is an authoritative `EditorSession` state with `following` and `paused` modes, the latest ordered change target, and a bounded queue of watcher-derived targets. While following, each accepted external-change event creates or updates that file's live diff tab, activates it in the session's active editor pane, and computes a separate scroll offset for every client view so the newest changed hunk is visible within that client's dimensions. A dirty-buffer conflict still drives the diff/follow transition using disk content, while leaving the editable buffer unchanged. A user-originated scroll, tab choice, pane focus, cursor move, Goto/Search result choice, panel navigation, or other navigation command transitions the session to `paused` before applying that navigation. The initiating client's scroll offset changes; other clients' per-view scroll offsets do not, though all clients observe the shared paused state and tab/pane choice. Background/programmatic navigation does not pause it. The footer displays the paused state and the binding for the stable `follow_edits.resume` command. A queued target is valid when its stable file identity still resolves beneath the CWD and its current diff model contains at least one hunk; rename resolution and deletion hunks remain valid, while reverted changes do not. Resuming activates the newest valid target in the active pane, computes per-client scroll offsets to its newest hunk, clears older targets, and returns to `following`; if no valid target remains, it returns to `following` without moving. Because follow mode, targets, active tabs, and every client's view state live in the library, in-process and WebSocket clients observe the same semantic transitions. A manual navigation from any attached client pauses following for all clients.

Goto Anything performs fuzzy matching across workspace-relative files; prefixes or typed query modes select symbol, line, and text search. Search and navigation are cancellable and stream ranked results tagged with the source revision. Results from an obsolete revision are discarded. Syntax highlighting uses Tree-sitter when a grammar is available and a plain-text fallback otherwise. Parsing is incremental and must never block command processing for an unbounded interval.

LSP is a P0 headless service adapter. SSG owns document synchronization, version mapping, cancellation, diagnostics, completion, hover, definition, reference, rename, and workspace-edit validation. An injected process/stream adapter owns server launch and I/O so embedders can supply their own process model. LSP UTF-16 positions are converted only at the adapter boundary and are tested against independent UTF-8/UTF-16 fixtures. Workspace edits are validated completely before any document is mutated.

Lua plugins execute through a versioned SSG Lua API. A plugin can register commands, key bindings, event handlers, tree providers, syntax metadata, and buffer transformations. Each explicitly constructed `LuaCommandHost` owns one isolated Lua state; constructing or using the basic editor does not construct a Lua state. C++ objects are exposed as non-owning handles containing an index and generation into a host-owned slot table. Invalidation increments the generation before slot reuse, and stale access returns a typed Lua-host error. Plugin callbacks run on the session command thread with instruction/time budgets and explicit error isolation. The host injects the catalog-command dispatcher and an immutable plugin principal whose origin is `lua` and whose capabilities are exactly the host grant; later session assembly routes that dispatcher through the common command boundary. The Lua state provides no package discovery or native-module loader, and does not open filesystem, process, network, or debug libraries. Plugin loading from explicit host-provided script paths may be supplied by the host; online discovery, dependency resolution, publishing, and package registries are excluded.

`HttpEditorServer` in the SSG adapter layer composes `../http`; `../http` remains independently buildable and SSG does not copy its socket implementation. P0 includes porting the required `../http` server and WebSocket surface to Linux and Windows behind its own platform socket adapter. Each connection has an SSG-owned bounded outbound queue and one writer task, so editor command processing never calls a socket send directly. `../http::Server::send()` must accept a write deadline, complete partial writes, and return a typed result distinguishing success, timeout/backpressure, and closed/error on both platforms. Timeout or queue overflow causes SSG to close the connection deterministically; no second unbounded queue is permitted below SSG. The server maps each connection to a protocol version, authenticated host-created session ID, client ID, and queue. One ordered connection carries all client commands, capability responses, snapshots, deltas, status actions, clipboard requests/responses, and binary payloads; no behavior depends on an out-of-band channel. A reconnecting client supplies its last applied session revision; the server replays retained deltas or sends a fresh snapshot when replay is unavailable.

Each per-client snapshot includes the immutable capability IDs granted to that principal, allowing clients to render only authorized affordances. Capability grants themselves are host policy and cannot be added or changed by a client command, Lua plugin, transport payload, or IP-address inference.

Themes are immutable values and the single source of truth for all color. Each contains exactly 16 indexed sRGB colors (`0..15`). The scoped semantic-role and syntax-scope catalogs are exhaustive; every theme maps every catalog entry to a palette index, and unknown syntax scopes deterministically resolve to the cataloged plain-text role. Neither mapping may introduce additional colors, literal client/plugin colors, alpha variants, gradients, or computed shades. The authoritative co-visibility relation is shared by every theme and recorded in `tests/fixtures/theme_roles.json`: selection/caret, diagnostic severities, Git states, tree focus, and tab/panel states map to distinct indices within each class; roles that cannot be co-visible may share an index. Theme construction rejects missing, duplicate-index, or extra palette entries and missing, duplicate, unknown, or extra role mappings. Snapshots carry the palette and complete mappings in palette/catalog order, making equal theme snapshots deterministic. This preserves deterministic browser, desktop, and ANSI/TUI presentation.

High performance is achieved by bounded command work, incremental document/syntax/layout updates, shared immutable snapshots, and deltas proportional to the changed region rather than full-session serialization. The P0 editor targets normal text files up to 10 MiB; very-large-file mode is explicitly deferred. No renderer, HTTP dependency, LSP process, or Lua plugin is required to construct and use the basic in-process editor.

## Foundation infrastructure

`include/ssg/types.h` provides unconstrained strong-id types shared across all feature components: `Revision` (totally-ordered session revision; `Revision{0}` is the null sentinel), `ByteOffset` (zero-based byte offset into a UTF-8 buffer), `LineIndex` (zero-based line number), `CellIndex` (zero-based display-cell index within a rendered line), and `DocumentPosition` (the three coordinates together, as they appear at API boundaries). It also defines `DocumentMode` (`edit`, `read_only`, `diff`). All constructors are constexpr and noexcept with no validation, because these types represent unconstrained ordinals; the spec states that stale or inconsistent positions produce a typed protocol error at the consuming boundary, not here.

`include/ssg/config.h` provides immutable construction-time configuration aggregates: `IndentStyle`, `LineEnding`, `TabWidth` (validated to `[1, 16]`), `HistoryConfig`, and `IndentConfig`. These are fixed at object-construction time. They differ from `SettingsModel` (owned by the `settings-model` feature): `config.h` types encode invariant construction parameters; `SettingsModel` owns runtime-adjustable, multi-scope, persistent settings with delta publication. When a component needs settings that change during a live session, it receives them through `SettingsModel`; when it needs fixed construction parameters, it receives them through `config.h` types.

Construction failure: validated `config.h` types throw `std::invalid_argument` with an actionable message for out-of-range inputs (I4). Types with no domain constraint (all of `types.h`) never throw from their constructors.

The build system uses `cmake/components/*.cmake` manifests for component-local source and test registration. The root `CMakeLists.txt` captures `SSG_SOURCE_DIR = CMAKE_CURRENT_SOURCE_DIR` immediately after `project()`, then creates the `ssg` library, calls `enable_testing()`, and globs manifests in sorted order with `CONFIGURE_DEPENDS`. `SSG_SOURCE_DIR` is SSG's own source root regardless of whether SSG is the top-level project or an `add_subdirectory` dependency; manifests must use `${SSG_SOURCE_DIR}` for all project-root-relative paths and must never use `CMAKE_SOURCE_DIR` (which resolves to the host project root in subdirectory mode). A manifest may call `target_sources(ssg PRIVATE ...)` to add library sources and, inside `if(SSG_SOURCE_DIR STREQUAL CMAKE_SOURCE_DIR)`, add and register standalone test executables (this guard is false in subdirectory mode, so host projects are not contaminated with SSG's internal test targets). All manifest target names must be unique across manifests. The sanitizer toggle `SSG_SANITIZE=ON` enables AddressSanitizer and UBSanitizer (Clang and GCC) by applying flags to the `ssg` target as `PUBLIC` so test executables inherit them. The `tests/consumer/` project is the `add_subdirectory` oracle: it loads SSG as a subdirectory, builds a minimal consumer executable, and confirms SSG test targets are invisible to the outer CTest.

## Invariants

- **I1 — Headless core:** Editor behavior is usable through the C++ library without HTTP, a renderer, browser APIs, terminal APIs, `../gridui`, or an event-loop framework.
- **I2 — Single behavior path:** In-process and WebSocket clients execute the same command implementation and observe the same ordered snapshot/delta model.
- **I3 — Authoritative revisions:** Accepted state changes are totally ordered; clients never apply a delta to a different base revision.
- **I4 — Valid state by construction:** Public owning objects are RAII-managed, construction establishes validity, ownership is explicit, and failures are actionable.
- **I5 — Atomic edits:** A failed edit or workspace edit changes no document; every accepted transaction belongs to exactly one undo unit, and only explicitly compatible adjacent transactions may coalesce.
- **I6 — Portable input:** Every required command has a default browser-deliverable binding shared by Chromium, Firefox, and WebKit; required behavior never depends on an intercepted or browser-specific chord.
- **I7 — Renderer neutrality:** Core layout is a deterministic monospace cell model and contains no pixel, DOM, GPU, or terminal escape-sequence behavior.
- **I8 — Palette cardinality:** Every accepted theme contains exactly 16 indexed colors, and every visible semantic role resolves to one of them.
- **I9 — CWD boundary:** Workspace-relative identity and default filesystem authority are rooted at the canonical CWD.
- **I10 — Bounded extension failure:** Lua, LSP, tree providers, search, parsing, and transport clients cannot block the session indefinitely or leave partially applied state.
- **I11 — Protocol compatibility:** Every wire message is versioned, bounded, validated before mutation, and either accepted wholly or rejected with a typed error.
- **I12 — Core independence:** Optional adapters and services are separately linkable; unused Lua, LSP, HTTP, Tree-sitter, and renderer integrations impose no runtime initialization.
- **I13 — Independent oracle:** The reference editor is a minimal implementation that shares no editing, selection, or history code with SSG and passes its own hand-computed unit cases before it validates SSG.
- **I14 — Shared follow state:** Watcher-driven tab, diff, pause, resume, and target transitions are authoritative shared library state; each client's authoritative library-owned scroll offset may differ only to fit its viewport dimensions.
- **I15 — Shell geometry:** Every supported-size UI snapshot has one full-width header row, one full-width footer row, and a non-overlapping middle whose editor uses one shared tab row and one scrollbar column for each visible pane. `viewport_too_small` is a typed error state, not a UI snapshot.
- **I16 — API completeness:** Every interaction and observable view flows bidirectionally through the typed command/snapshot/delta API and can use one ordered WebSocket connection without an out-of-band behavior channel.
- **I17 — Backend boundary:** The backend owns editor and view-model semantics but contains no platform input capture, DOM, terminal, pixel, glyph rasterization, or rendering implementation; clients contain no editor behavior.
- **I18 — Browser feasibility:** A feature is admissible only when a standards-based browser client can complete its workflow through available browser capabilities and the SSG API.
- **I19 — Non-modal reversibility:** No command requires a blocking dialog. State-losing major actions take effect immediately and create a bounded recovery or compensating command before loss.
- **I20 — Lua command parity:** Every user-visible command except lifecycle, transport authentication, raw platform I/O, host capability grants, and explicitly cataloged capability-gated ingress commands is callable through the versioned Lua API.
- **I21 — Required platforms:** Core behavior, filesystem watching, scratch recovery, file I/O, and HTTP/WebSocket service pass parity gates on Linux and Windows.
- **I22 — Color authority:** `Theme` is the only source of color values; all clients and extensions consume its 16 colors and semantic indices through the API.
- **I23 — Caret visibility:** After any accepted command that moves or recreates the primary selection, every displaying client view minimally scrolls as needed to keep its primary caret visible.

## Considerations

- **Concurrency:** One session command executor serializes mutations. Background workers operate on immutable revision-tagged inputs and post cancellable results; they never mutate session state directly.
- **Lifetimes:** Snapshots and deltas are move-only owning values with immutable payloads and no implicit shared ownership. Const access from multiple threads is safe while the owning value remains alive; moving or destroying it requires external exclusion. Fan-out requires explicit cloning or serialization. Callback arguments are valid only for the callback unless explicitly copied.
- **Backpressure:** Search results, diagnostics, syntax deltas, file events, and socket output are bounded and coalesced. Text edits and close/save decisions are never silently dropped.
- **Protocol limits:** Hosts configure maximum message, snapshot, binary frame, queue, session, client, tab, and document sizes. Defaults are finite and covered by rejection tests.
- **Unicode:** Byte offsets are canonical for document mutation; grapheme/cell and LSP UTF-16 conversions are boundary concerns. Fixtures cover combining marks, emoji sequences, CRLF, invalid UTF-8, and double-width glyphs.
- **Filesystem safety:** Canonicalization, symlink traversal, rename races, case sensitivity, atomic save, permissions, external modification, and newline preservation require explicit errors and tests.
- **Browser input:** The conformance manifest records required actions and default bindings, and automated browser tests prove events reach the client and suppress browser behavior where applicable.
- **Client locality:** Local-only capabilities are granted by authenticated host policy, never by a client assertion or IP-address guess. Remote and locality-unknown connections cannot invoke `file.open_dropped_content`.
- **Multiple clients:** P0 guarantees ordered observation and rejects stale mutation commands; simultaneous collaborative conflict resolution and shared cursors are not promised.
- **Persistence:** Session state stores relative paths, tab/split topology, active views, panel state, keymap/theme names, and unsaved-buffer recovery separately. Corrupt or newer state fails safely without preventing a clean session.
- **Watcher ordering:** Coalescing preserves the final event and rename identity. Events carry watcher sequence and observed file metadata; stale reads and out-of-order background diff results are discarded at the session boundary.
- **Follow interruption:** Commands declare whether they are user navigation, programmatic navigation, or non-navigation. Input source alone is insufficient because a Lua or transport command may represent deliberate user navigation.
- **Diff conflicts:** Dirty buffers are never silently replaced by disk changes. The diff tab shows disk-versus-index state while the editable tab retains unsaved content and exposes explicit reload, keep-buffer, and open-diff actions.
- **Small viewports:** The minimum supported grid is 20 columns by 4 rows. Below it, clients receive a typed `viewport_too_small` state rather than malformed geometry.
- **No package service:** Lua extensibility is an API and loader only. SSG does not define package metadata, remote catalogs, dependency solving, publishing, or trust ratings.
- **Cross-platform:** Linux and Windows are required for the core, in-process interface, filesystem watcher, recovery store, atomic file operations, and `../http` WebSocket adapter. macOS is allowed but does not replace either required platform gate. Platform path, identity, permission, newline, cache-directory, and socket differences are normalized at adapter boundaries. Windows adapters reject or encode reserved device names, invalid path characters, trailing dots/spaces, and paths beyond the selected Win32 long-path policy before mutation.
- **Non-modal errors:** Failed commands leave state unchanged where atomicity permits, publish actionable footer status, and remain scriptable through command IDs. Status actions replace confirmation dialogs.
- **Undo scope:** Text transactions use per-file undo/redo. Workspace replacement, close, reload, overwrite-save, rename, and delete use bounded recovery records; navigation, status dismissal, remote connection lifecycle, and external process effects are not promised general undo.
- **Binary and encoding:** NUL-containing files open read-only with binary status unless a future browser-capable binary editor is specified. Invalid UTF-8 never undergoes implicit replacement; explicit conversion is a separate reversible command.
- **Presentation scale:** Zoom and font size are client rendering preferences. They affect the viewport dimensions submitted through the API, not editor semantics or library-owned font state.
- **Stretch isolation:** DAP follows the LSP-style injected I/O boundary; desktop rendering depends on `../gridui`; binary stream tabs use protocol capabilities; very-large-file work may replace storage internals without changing commands or view contracts.

## Risks and Mitigations

- **Text storage choices could prevent large-file work:** Keep `Document` behind command/snapshot interfaces, benchmark representative edit patterns, and avoid exposing storage iterators or contiguous-buffer assumptions.
- **Cell layout may disagree across clients:** Pin Unicode data, publish golden cell-run fixtures, and require every client to pass them.
- **Browser shortcut interception may make commands unreachable:** Maintain a cross-browser reserved-binding denylist and run real-browser key conformance tests for every required action.
- **Lua plugins may compromise stability or security:** Use per-session states, capability grants, checked handles, execution budgets, bounded errors, and no native modules by default.
- **LSP edits may corrupt newer documents:** Map protocol versions to document revisions and reject or rebase only through an explicitly tested transaction path.
- **Incremental services may produce stale output:** Revision-tag all asynchronous work and discard obsolete results at the session boundary.
- **WebSocket clients may exhaust memory:** Enforce limits before allocation, bounded queues, coalescing, replay windows, and deterministic slow-client disconnects.
- **Exactly 16 colors may reduce legibility:** Require semantic contrast fixtures for bundled themes and allow role remapping, never hidden extra colors.
- **Watcher storms may thrash tabs and diffs:** Debounce by file identity, cancel obsolete computations, bound the target queue, and emit only the newest revision-tagged result per file.
- **Follow-edits may fight user intent:** Every deliberate user navigation pauses before movement, the footer makes the state and resume binding visible, and resume jumps only to the newest valid target.
- **Git baselines may race index or branch changes:** Tag results with repository/index identity and discard results whose baseline changed before publication.
- **Shared navigation may surprise multiple clients:** Treat session-wide following, active tab, and active pane as explicit P0 product rules while retaining per-client viewport dimensions and scroll offsets. Show the same footer state everywhere and cover cross-client interruption plus per-client movement in the protocol oracle.
- **Broad P0 scope may delay a usable vertical slice:** Build one thin end-to-end path first—document edit through in-process and WebSocket clients—then add services behind the stable protocol.
- **Scratch data may expose sensitive text or grow without bound:** Use user-only permissions, checksums, configurable byte/age quotas, atomic compaction, explicit purge commands, and no network synchronization.
- **Clipboard APIs may be denied or asynchronous:** Keep the internal register authoritative for editor operations, treat system clipboard exchange as revision-tagged best effort, and ignore stale client responses.
- **Piece-tree complexity may hide edit bugs:** Keep representation private and compare randomized multi-cursor transactions plus undo/redo against the independent reference editor.
- **Immediate destructive actions may surprise users:** Surface the compensating command in the footer and keep bounded recovery records before applying close, reload, overwrite, rename, delete, or workspace replacement.

## Rationale (optional, skippable)

The design adopts Sublime Text’s strongest user-valued qualities—speed, editing fluency, keyboard navigation, minimal presentation, customization, cross-platform consistency, splits, and syntax support—without making the core an application shell. A single command/snapshot/delta seam prevents the TUI, browser, and future desktop client from becoming separate editors. The 16-color cell model deliberately favors deterministic TUI parity and compact updates over unrestricted GUI styling. Lua supplies local programmability while explicitly avoiding the operational and compatibility burden of a package distribution service.
